# 2026-09-24：6 ms PID 离线准备

20 ms 基线已先提交并推送：`a1d0197cbe28849eeec69b19a9d41d19eb5818d5`。
本次没有连接机器人，没有创建 DDS participant、publisher 或发送模式／行走／关节命令。

## 采用的最小改动

- 控制周期 20→6 ms，三秒进入／十秒走动／18 秒结束航向保持／至少三秒退权的流程保持。
- 右臂重力误差雅可比改成一次 FK 和解析 site Jacobian。使用同一 XML、同一瓶身中心，
  没有新增近似机器人模型。普通 PID 结构和既有增益保留，积分项仍关闭。
- 真机任务修正固定按旧 20 ms 参考周期换成速度，避免仅改 dt 就放大 3.33 倍；导数滤波按
  物理时间换算，6 ms 时 alpha=0.0215359257。差分／积分用实测循环间隔，命令积分最多 6 ms。
- 控制线程单核、BLAS 单线程、普通调度。固定时间槽并跳过过期槽，记录实际周期、deadline、
  状态年龄／复用、DDS 本地写耗时。速度／加速度限制、±5° 和慢退权保留。
- 20 ms 版本的 SDK listener 关闭顺序修复保留，增加关闭时 Python listener 的生命周期保持；
  尚待下一次实机验证退出阶段。没有修改外部 SDK。

时间换算意味着“更新周期与仿真一致、物理强度沿用已验证真机基线”，不意味着仿真与真机带宽完全相同。
没有为了追求稳杯效果重新调 Kp/Kd，没有改 MPC，没有迁移 C++ 或修改系统实时策略。

## 离线验证

19 项 PID／分析测试通过：包括 120 个随机姿态的解析／数值雅可比对照、相同周期时 PID 输出等价、
物理滤波时间常数与任务强度不随周期变动、deadline 跳槽、6 ms 输出范围与三秒退权，以及原有
拒绝输出／完整 `[5,18)` 评价测试。雅可比对照使用绝对容差 `3e-8`、相对容差 `3e-7`。

deadline 指该时间槽开始后 6 ms 以前完成上述工作；因此偶发 8.661 ms 的起始间隔和零 deadline miss
并不矛盾。两项分别记录，不把普通 Linux 描述成严格实时。

旧真机记录 PID 计算 p95 为 16.312 ms、最大 28.949 ms，但旧记录含真实 DDS 回调等并发负载，
不能用这两组数值宣称同条件加速倍数。新回放不包含真实 DDS 接收解码／回调竞争、RPC 工作者及
电机执行延迟。源文件的完整 LowState 约 20 ms 记录一次，评价段有 1554 次复用 LowState，
不能将其理解成 6 ms 真机接收丢包。新增现场日志会单独统计实时输入年龄和复用。

当前运行环境不允许绑定 CPU 7，所以改用允许的 CPU 2，并记录亲和性。此前的 CPU 7 尝试在
回放开始前拒绝，留在本地 `pid_6ms_offline_20260924/`；它不属于成功证据。

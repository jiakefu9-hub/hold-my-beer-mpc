## C 究竟改了什么

独立配置：`configs/hardware_acceleration_pid_20261012.yaml`。
最终选择允许少量末端姿态退步的候选，而非倾角最小的组合：

| 项目 | 旧仿真 C | 本次 T03/T05 |
|---|---:|---:|
| 任务姿态 Kp / Ki / Kd | 900 / 50 / 60 | 400 / 50 / 40 |
| 线加速度分配权重 | 0.1 | 0.4 |
| 分配正则 | 0.003 | 0.012 |
| 关节回中 kp / kd | 4 / 2 | 24 / 8 |
| 积分限幅 | ±0.1 | ±0.1 |

这里的任务增益不是底层发包 PD。降低任务姿态反馈、提高关节回中是不同作用；
后者用于减少肩部运动/接触，确实收回了部分线加速度收益。最终标准仿真加速度收益仅约0.8%，
不预设明天的实机加速度一定更低。

共同 MPC YAML 只为 C 提供运行时接口与接管时序，**其中 MPC 的 q_ee_acc、q_gravity 等权重不参与 C 的求解**。
生效的 C 参数以独立 YAML 和每轮保存的 `acceleration_pid_config.yaml` 为准。

1. 当前实测右臂 q/dq 和 H0 身体姿态形成当前端点倾斜误差，实测身体角速度与关节速度形成端点角速度。
2. 倾斜 P/I 与三轴角速度阻尼 D 产生任务角加速度目标。
3. 只取学习预测的首个线/角加速度区间，使用与 MPC 相同的移动基座运动学项。
4. 一次五变量加速度分配兼顾姿态修正、线加速度和关节回中。无约束解可行时直接采用；
否则用五变量 DAQP 求受约束最小二乘。没有 9 步关节轨迹优化，不是另一套 MPC。
5. 使用已有实测移动基座输入的耦合五自由度右臂模型计算总力矩 M*a+b，
   发包 tau=总力矩−packet_PD，固件只补回一次 PD。

与原仿真 C 的区别：仿真旧 C 在无约束分配后逐关节裁剪；真机 C 在分配时纳入下一拍 q/dq/a、
总力矩、前馈力矩和已有提前制动边界。约束生效时冻结积分，积分仍有限幅。
不把完整 MuJoCo 接触求解器移到真机，也不在线辨识或训练预测器。
当前状态完全保持实测；`--align-accel-forecast` 只调整未来区间加速度取样，
C 使用调整后的第一段，MPC 使用九段。该开关不是完整执行器延迟补偿。
时间预算仍沿用原日志的3.5 ms，不代表已辨识出C的电机生效时间。

原总/前馈力矩限值均保持 `[10,6,4,7,1.5] Nm`，dq=5 rad/s、ddq=15 rad/s²。
本轮两种控制器共用独立的 `configs/hardware_control_comparison_20261012/torque_common.yaml`：
右肩roll正常规划范围从原[-15,+15]°收紧为[-15,+1]°，外边界从[-20,+20]°收紧为[-17,+3]°。
正roll向内，负roll向外；2°缓冲用于原有制动/回入，并非允许任意碰撞。
其余关节范围、力矩和底层PD不变。正常范围和外边界不同，不能把+1°称为实测绝不越过的硬限。
原75 mm模型中，其余右臂角为零时，roll +3.5°已有肩部接触；+3°该姿态无接触。
其他肩肘组合仍可能碰撞，所以这个关节角矩形不是完整避碰约束，也不能证明真机安全。
本轮还统一把接管过渡从1.5 s调整为1.2 s，起点仍为3.3 s，结束从4.8 s提前到4.5 s。
这是缩小roll范围后的配套调整：条件模型里，旧1.5 s过渡在180354输入、零附加延迟时，
MPC曾到+3.009°而退出；仅缩小正常范围未解决。1.2 s在同一检查下通过，
不是修改控制频率，也没有新增静止接管环节。该时序尚未真机验证。
T01～T06统一使用新边界和新接管时序；与旧164546/此前仿真数值的直接差异包含边界与负载变化，不能只归因于控制器。

标准、另一初态及75 mm仿真无肩部接触；4 ms延迟仿真仍有21帧肩部接触，这是已知局限，
不是“全部鲁棒性测试通过”。更软150/25候选的条件模型接管有边界失败，因此未安排在此实验单。

保留的历史回退文件是 `hardware_mpc_learned_acc001_alpha0005_omega1.yaml`
与 `hardware_mpc_torque_learned.yaml`；使用它们才是原权重/原边界/原1.5 s过渡。
新默认共同配置为 `hardware_control_comparison_20261012/mpc_baseline.yaml`，T06为同目录的`mpc_acc002.yaml`。
原 torque 文件保留不改；本轮显式选择上述独立文件，底层 PD 不变。C 不使用 MPC 的 pitch/yaw 输入坐标变换代价；
它用自身加速度回中项，yaw 的原固定发包角度和小 PD 仍保持并在力矩分配中准确扣除。
左臂、行走程序、H0 定义、日志和评价时窗保持一致。

## 评价与证据

现场统一 `[5,18)`，另分行走与停车；完整报告左右：竖直倾角均值、相对平均瓶轴摆动 RMS、
三维线加速度、角加速度、角速度和可观测的速度指标。真机没有可靠绝对平移速度时，
只报告相对 torso IMU 的端点速度，不将仿真世界系速度直接当成同一个指标。
同时比较身体激励、关节/力矩余量、6 ms 耗时和超期、停车与最终零权重。

软件离线证据、仿真结果与 C 最终参数选择见
[本轮研究报告](../../simulation/experiments/20261012_c_refinement/REPORT.md)。
只要操作者没有主动报告现场异常，沿用现有约定视为有效；程序中止或日志缺失仍按实际情况记录。
日志协议保留原兼容字段 `mpc_active` / `raw_mpc_ddq_rad_s2`，但 session.controller_variant、
core.model、actual_control_family 明确标记 C，不能仅按旧字段名字把它算成 MPC。

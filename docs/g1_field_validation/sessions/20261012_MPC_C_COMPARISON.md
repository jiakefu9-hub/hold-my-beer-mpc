## C 究竟改了什么

独立配置：`configs/hardware_acceleration_pid_20261012.yaml`。
最终选择允许少量末端姿态退步的候选，而非倾角最小的组合：

| 项目 | 旧仿真 C | 本次 T03/T05 |
|---|---:|---:|
| 任务姿态 Kp / Ki / Kd | 900 / 50 / 60 | 400 / 50 / 40 |
| 线加速度分配权重 | 0.1 | 0.4 |
| 分配正则 | 0.003 | 0.012 |
| 关节回中 kp / kd | 4 / 2 | 24 / 8 |
| 积分限幅 | ±0.1 | ±0.1 |

这里的任务增益不是底层发包 PD。降低任务姿态反馈、提高关节回中是不同作用；
后者用于减少肩部运动/接触，确实收回了部分线加速度收益。最终标准仿真加速度收益仅约0.8%，
不预设明天的实机加速度一定更低。

共同 MPC YAML 只为 C 提供运行时接口与接管时序，**其中 MPC 的 q_ee_acc、q_gravity 等权重不参与 C 的求解**。
生效的 C 参数以独立 YAML 和每轮保存的 `acceleration_pid_config.yaml` 为准。

1. 当前实测右臂 q/dq 和 H0 身体姿态形成当前端点倾斜误差，实测身体角速度与关节速度形成端点角速度。
2. 倾斜 P/I 与三轴角速度阻尼 D 产生任务角加速度目标。
3. 只取学习预测的首个线/角加速度区间，使用与 MPC 相同的移动基座运动学项。
4. 一次五变量加速度分配兼顾姿态修正、线加速度和关节回中。无约束解可行时直接采用；
否则用五变量 DAQP 求受约束最小二乘。没有 9 步关节轨迹优化，不是另一套 MPC。
5. 使用已有实测移动基座输入的耦合五自由度右臂模型计算总力矩 M*a+b，
   发包 tau=总力矩−packet_PD，固件只补回一次 PD。

与原仿真 C 的区别：仿真旧 C 在无约束分配后逐关节裁剪；真机 C 在分配时纳入下一拍 q/dq/a、
总力矩、前馈力矩和已有提前制动边界。约束生效时冻结积分，积分仍有限幅。
不把完整 MuJoCo 接触求解器移到真机，也不在线辨识或训练预测器。
当前状态完全保持实测；`--align-accel-forecast` 只调整未来区间加速度取样，
C 使用调整后的第一段，MPC 使用九段。该开关不是完整执行器延迟补偿。
时间预算仍沿用原日志的3.5 ms，不代表已辨识出C的电机生效时间。

原总/前馈力矩限值均保持 `[10,6,4,7,1.5] Nm`，dq=5 rad/s、ddq=15 rad/s²。
本轮两种控制器直接共用成功基线 `configs/hardware_mpc_torque_learned.yaml`。右肩roll外边界为[-20,+20]°，
5°裕量后的正常规划范围为[-15,+15]°；力矩、速度、加速度和底层PD也保持原值。
接管保留成功配置的3.3 s起点和1.5 s过渡，在4.8 s结束。

第一次T01曾临时将roll正常范围收紧为[-15,+1]°、外边界收紧为[-17,+3]°，并把接管缩为1.2 s。
真机在行走约2.2 s后，roll仅略过+1°但速度约+1.16 rad/s，未来轨迹约束不可行，DAQP退出并完整安全退权。
这轮不能用于性能比较。故障表明这组额外边界不适合当前步态，而不是原MPC权重失效；该改动已经撤销，后续不再原样运行。
T01～T06与旧164546的共同差异只保留零中立位和75 mm负载，具体控制器差异按编号逐项加入。

标准、另一初态及75 mm仿真无肩部接触；4 ms延迟仿真仍有21帧肩部接触，这是已知局限，
不是“全部鲁棒性测试通过”。更软150/25候选的条件模型接管有边界失败，因此未安排在此实验单。

T01～T05直接使用 `hardware_mpc_learned_acc001_alpha0005_omega1.yaml`
与 `hardware_mpc_torque_learned.yaml`；T06只使用同目录下独立的`hardware_control_comparison_20261012/mpc_acc002.yaml`。
两个成功文件保持不改，底层 PD 不变。C 不使用 MPC 的 pitch/yaw 输入坐标变换代价；
它用自身加速度回中项，yaw 的原固定发包角度和小 PD 仍保持并在力矩分配中准确扣除。
左臂、行走程序、H0 定义、日志和评价时窗保持一致。

## 评价与证据

现场统一 `[5,18)`，另分行走与停车；完整报告左右：竖直倾角均值、相对平均瓶轴摆动 RMS、
三维线加速度、角加速度、角速度和可观测的速度指标。真机没有可靠绝对平移速度时，

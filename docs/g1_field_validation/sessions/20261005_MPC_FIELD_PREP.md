# 2026-10-05：力矩 MPC 整链优化与首次原地试验准备

## 结论与边界

6 ms PID 现场功能基线已先提交同步：`7c3db04af31fc0821b8b5a8eb5186165ef4c7c7f`，
见 [PID 现场记录](20261005_PID_6MS_FIELD.md)。本次后续工作没有发出真实 MPC 命令。

力矩 MPC 已具备显式开启的受控首次**原地**试验软件入口；仍保留 **6 ms**。
最终两轮离线整链平均 5.079／4.963 ms，P99 5.940／5.438 ms，超时 1.168%／0.324%。
保留所有约束、候选和完整日志，不用删检查来制造达标。两轮不能证明最坏执行时间，
更不能证明 DDS 负载下零超时或机器人效果。先原地获取真实力矩／加速度响应，再决定行走。

为什么暂不降频：已有大多数周期在 6 ms 内完成，原地任务不查询行走预测库，有额外余量；
下一项有价值的证据是实机原地闭环及 DDS 时间，而非现在把模板的物理时间轴整体改掉。
若真实整链持续超时，应停止、分析再决定周期，不把偶发跳槽当作正常的低频控制设计。

## 保留了什么，改了什么

- 实测 q/dq 经已发命令历史估计假定执行时刻状态；MPC 不是从积累的参考状态出发。
- 九段 6 ms 加速度 MPC、仿真运动学／代价、逆动力学、局部力矩修正、多候选正动力学筛选保留。
- 质量矩阵逆提供当前模型的精确仿射增益，替代重复有限差分；候选批量计算，最终独立检查保留。
- QP 使用同一块对角 Hessian 做凝聚，避免乘大块零矩阵；重建完整轨迹后继续检查全部约束。
- 扰动库采用精确欧氏距离的连续数组扫描，仍取同样八个邻居与相同权重，没有改成近似模型。
- 延迟的 2 ms 小步计算移至 SDK-free C++／MuJoCo；模型、积分和命令切换不变，源码与库哈希入记录。
- 日志在入队前形成不可变快照，用 `orjson==3.11.3` 减少 Python 遍历；候选数据没有被删掉。
- 固定 H0、250 g/手、冻结模型、2 ms 因果滤波及 6–54 ms 预测时距不变，没有重训或缩放模板。
- 新增独立首次力矩配置、非零前馈故障交还；PID 增益／积分规则／调度周期不改。
  共享 runner 只增加 MPC hook、可覆盖的日志编码，以及成功 Write 后先锁存命令再做日志。

现场五轴总力矩估计／前馈限值 `[5,3,2,5,1.5] N·m` 是试验工程限值，**不是厂家额定值**。
PID 的 `tau_est` 只提供量级参考，不是标定。保留原外层关节角度边界、dq/ddq 约束和制动预测边界。
正常／可处理故障退权保留最后成功包的完整 PD＋前馈关系，weight=0 才清零 tau；
模式切换、失联或写失败不继续发送。不能保证强杀／断线时的固件行为。

## 主机设置

- 内核 `6.8.1-1057-realtime`，PREEMPT_RT；原有 `isolcpus=domain,managed_irq,6-7`、
  `nohz_full=6-7`、`rcu_nocbs=6-7`；本轮未修改启动参数或 IRQ 配置。
- 控制线程 CPU 7、SCHED_FIFO 20；DDS／日志／RPC 工作线程在创建时避开同物理核的 6–7。
  数值库线程数固定为 1；不能把“线程绑核”解释成任何其他系统线程都不可能干扰。
- 操作者给启动终端 `RLIMIT_RTPRIO=40`、CPU 6–7 governor=performance。
- 后续将整机 `powerprofilesctl` 从 balanced 改为 performance；最终两轮记录均确认生效。
- 结束后可恢复 `powerprofilesctl set balanced` 和
  `sudo cpupower -c 6-7 frequency-set -g powersave`。RT 权限只属于该终端及其子进程；
  新终端需重新设置，程序不会自行使用 sudo。性能档可能增加功耗和温度。

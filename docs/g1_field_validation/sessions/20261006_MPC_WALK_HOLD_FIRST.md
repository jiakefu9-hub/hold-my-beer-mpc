  因需要密码未执行，未假称已改；沿用此前原地成功的主机设置。

  共成功发送 13 拍 MPC 活跃命令，最后一拍 t=5.088429 s。
- t=5.040209 / 5.090327 s 两次 0.5 m/s 请求返回码均为 0；不等于实测速度或实际距离。

  因异步计算，最后一条成功发送的包不能当成失败这次求解的输出。

  软件停车回复不等于独立测得身体已零速度；这里记录的是本轮实际观察，不扩展成所有异常路径已验证。

## 已确认的失败原因范围

成功发送的 13 拍核心计算平均 4.042 ms、最大 5.040 ms；失败拍 QP 求解墙钟约 0.374 ms。
本次直接拒绝原因是求解失败，**不是计算超过 10 ms**，也不是学习预测查表耗时。

故障诊断保留的右肩 pitch 状态（已由模型推到假定命令执行时刻）：

- q = −0.0218321927 rad（−1.25089°），dq = 0.696295750 rad/s。
- 原始观测 q = −0.0264252163 rad，dq = 0.578310788 rad/s；模型向前预测约 7.195 ms。
- 外层角度上限 +5°，恢复余量 0.15°；当前包络要求预测节点 `q + dq/6 ≤ 4.85°`。
- 控制周期 dt=0.006 s，加速度下限 −8 rad/s²。

即使第一拍取最大允许减速度 a=−8：

```text
q_next = q + dt*dq + 0.5*dt²*a
dq_next = dq + dt*a
q_next + dq_next/6 = 5.170994° > 4.85°
```

该表达式随 a 单调增加，因此任何更大的 a 也不能满足此上限；仅这一条约束已足以说明
**失败状态下当前 QP 不可行**，不是只根据求解器返回码猜原因。
实现依据：`hardware_mpc_recovery.py` 从第一个预测节点起附加包络，
配置来自本轮 `torque_config.yaml` 与 session 中保存的展开配置。

实测角度尚未越过外层角度限位；这不是宣称机器人关节已经越界，
也不是此前那种单个瞬时腕速度阈值触发停止。
起步与右臂姿态修正同时发生，执行时刻预测又改变了起始速度。
它们各自贡献多少、如何在保留边界的同时获得可行恢复轨迹，仍需离线复现判断。
`fallback_feasible=true` 不能作为绕过条件：整体求解未成功，代码没有把该回退值送给机器人。

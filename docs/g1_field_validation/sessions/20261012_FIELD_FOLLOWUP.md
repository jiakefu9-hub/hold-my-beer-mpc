## 为什么暂时不改时间对齐算法

T02/T04查询到主机写出中位耗时3.558/3.540ms，原预算3.5ms仍吻合。
C的相同耗时2.903/2.916ms，预算偏保守约0.6ms；目前没有证据表明这点误差导致了C的姿态摆动。
当前姿态、角速度和逆动力学输入不受对齐开关影响。

使用T01保存的因果预测与随后收到的IMU重建标签，在同一个[Write完成, +6ms)窗口评价：

| 预测取样 | 线加速度预测向量RMSE m/s² | 角加速度预测向量RMSE rad/s² |
| --- | ---: | ---: |
| 原取样 | 1.2049 | 3.5463 |
| 当前动态对齐 | 0.8275 | 2.3263 |
| 固定向未来移动3ms | 0.9016 | 2.5447 |
| 固定向未来移动6ms | 0.8401 | 2.4120 |
| 固定向未来移动9ms | 0.9991 | 3.0269 |

当前对齐没有明显时间戳错误；这些是滤波后、按主机收到时间定义的标签，不是电机执行时间或液体加速度。
离线误差改善没有转化成已证明的末端收益。T01只有一次，故下一轮先重复，不据此确定关闭更优。
证据：`evaluation/hardware_shadow/commissioning/timing_review_20261012_T01/summary.json`。

此前仿真消融中，只开3ms前视使线加速度2.5775→2.5245m/s²，约2.1%；
姿态预测校正、不同权重和运行范围另有贡献，不能把整体14.28%的改善归给前视。
见[原仿真报告](../../simulation/experiments/20261010_mpc_comprehensive/REPORT.md)。

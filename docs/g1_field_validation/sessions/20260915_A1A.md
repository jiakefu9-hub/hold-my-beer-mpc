## 2. 模式与服务：原始返回及解释

查询程序只注册四个 getter，不调用 `LocoClient` setter：

| 查询 | 返回码 | 原始值 | 本次可下的结论 |
| --- | --- | --- | --- |
| `sport.GetFsmId()` | 0 | 0 | 有效回应；按本地官方《软件服务接口》第 6 页为零力矩 |
| `sport.GetFsmMode()` | 0 | 0 | 有效原值；不能脱离 FSM=0，把它解读成正在自主平衡站立 |
| `sport.GetBalanceMode()` | **7301** | 0（程序默认占位值） | **未取得有效值**；不是已读到 balance_mode=0 |
| `motion_switcher.CheckMode()` | 0 | `form="0"`, `name="ai"` | 服务有回应；该字符串不等于正在运行 FSM=500，也不是固件版本 |

安装版 SDK 的 `include/unitree/robot/g1/loco/g1_loco_error.hpp` 定义：
`7301 = UT_ROBOT_LOCO_ERR_LOCOSTATE_NOT_AVAILABLE`，描述为 `LocoState not available.`。
官方 [G1 ROS2 客户端源码](https://github.com/unitreerobotics/unitree_ros2/blob/master/example/src/include/g1/g1_loco_client.hpp)
也使用相同定义。

因此这不是查询网络超时，也不能据此判断机器人损坏或接口永久不支持。当前是零力矩、
不是常规运控的背景值得保留，但 **7301 的具体触发条件本次未通过模式切换验证**。
没有为了让查询通过而切模式、重启服务或尝试其他编号。

查询工具报告 `a1_query_completed=true` 只表示流程完成，不表示四个 RPC 全部成功。
必须逐项检查返回码；本记录没有修改原始 JSON 里的占位值。

同一查询期间接收 LowState 229 帧、CRC 拒绝 0；最终快照：

| 字段 | 值 | 边界 |
| --- | --- | --- |
| `version` | `[0,0]` | 不能识别实际固件／ai_sport 版本 |
| `mode_pr` | 0 | 原始协议字段，不是阻尼／站立模式编号 |
| `mode_machine` | 4 | 原始机型相关字段；**不是**本次 FSM=4 |
| `tick` | 281432 | 原始 tick，不当作绝对时间 |
| 快照年龄 | 0.219055 ms | 捕获与校验的本机 monotonic 时间差 |

原始 35-slot `q/dq` 已保存至 `state_snapshot.conf`；槽数不等于实体关节数量。
单腰 yaw / Arm5 布局沿用用户已提供的信息，不宣称软件已识别完整商品型号。

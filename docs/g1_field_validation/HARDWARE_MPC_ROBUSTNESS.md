# 实测状态／力矩 MPC：延迟与负载偏差的离线验证

2026-09-28 开始，09-29 收尾。对应上一阶段的[力矩迁移说明](HARDWARE_MPC_TORQUE_MIGRATION.md)。
**本轮没有连接机器人、创建 DDS participant 或发送命令；新力矩路径仍禁止真机输出。**

**09-29 后续：已接入完整离线任务流程，见第 6 节。整链时间未通过，仍不能直接上机。**

## 1. 结论先说

- 原来的失败不能简单归因于“网络慢”：单独增加负载就会几乎贴住肩关节边界；延迟与失配叠加才使原版越界停止。
- 新增“提前减速约束＋命令生效时刻的状态预测”后，指定压力条件下的 **20 秒模型闭环完成**，没有越过原外层角度边界。
- 按相同 `[0,2.4)` 秒比较，加速度跟踪 RMSE 从 **1.12878 降到 0.84207 rad/s²，降低 25.4%**。
  这是五个关节的模型加速度误差，不是末端稳瓶改善百分比，也不是真机效果。
- **6 ms 整条路径仍未验收通过**。本节报告的阶段只接了离线研究器；后续完整任务集成和计时见第 6 节，不能拿不含它的旧计时结果宣称已经达标。
- 负载偏差下依然存在加速度误差。当前结果支持继续离线集成，不支持直接上机运行新力矩控制。

可直接看[对照图](../../evaluation_summary/hardware_mpc_robustness_20260928/comparison/comparison.png)和
[可追溯的数值报告](../../evaluation_summary/hardware_mpc_robustness_20260928/comparison/README.md)。失败尝试全部保留。

## 2. 怎样查出原因

控制器保持名义 250 g 瓶子模型，改变被控模型的单个因素。外层角度范围、速度、加速度、PD 和力矩限幅不变。
模型由右臂五关节及指定的身体运动组成，**不是全身行走仿真**。扰动预测使用解析已知轨迹，特意排除了学习预测器误差。

| 5 秒基线试验 | 结果 | 距原外层角度边界的最小余量 |
| --- | --- | ---: |
| 模型匹配 | 完成 | 1.000° |
| 仅瓶子质量／惯量 +20% | 完成，但几乎贴边 | 0.000205° |
| 仅摩擦 | 完成 | 1.000° |
| 仅观测延迟 4 ms | 完成 | 1.000° |
| 仅命令延迟 6 ms | 完成 | 1.000° |
| 观测 4 ms＋命令 6 ms | 完成 | 1.000° |
| 上述负载、摩擦和两种延迟一起 | 2.484 s 停止 | −0.005225°，已越界 |

摩擦假设为 `0.03*dq + 0.015*tanh(dq/0.02)` Nm。这些偏差和延迟是压力测试设定，不是实机测量结果。
每 2 ms 保存物理状态和当前真正生效的命令，避免只在 6 ms 时刻取样漏掉中间的越界。

旧的“实际加速度减最新请求”仍保存，但新增主指标是：

`实际加速度 − 此刻真正生效的那条命令所对应的期望加速度`

命令序号、生成时刻、观测时刻、生效顺序均有记录；初始未接管的保持段不计入这个 RMSE。
2 ms 连续保持期间 PD／身体状态会变化，因此不能把本轮 2 ms RMSE 与旧报告的 6 ms 抽样 RMSE 直接比较。

## 3. 改了什么，没有改什么

### 提前减速，而不是扩大关节范围

[`hardware_mpc_recovery.py`](../../tools/g1_commissioning/hardware_mpc_recovery.py) 保留原 QP 约束，
另外要求未来节点满足：`L+0.15° ≤ q+dq/6 ≤ U−0.15°`。
直观上，越靠近边界，允许继续向外的速度越小；同时修正原恢复逻辑在零 margin 关节上可能扩出外层边界的情况。
0.15°、6/s 都是离线设计值，不是实机安全认证。

**只加这个约束不够**：在延迟叠加下，0.114 s 就因为新的制动约束不可行而停止，虽然当时还没越过角度边界。
当时肩关节约 −1.586°、速度 +0.70690 rad/s；即使下一拍以 −8 rad/s² 制动，
`q+dq/6` 仍约 4.941°，大于允许的 4.85°。独立 LP 也无解。这个失败没有被删除或改称成功。

### 从观测向前估计，不是相信命令参考已经执行

[`hardware_mpc_delay_preview.py`](../../tools/g1_commissioning/hardware_mpc_delay_preview.py) 的输入只有：
本次观测 q/dq、观测时刻、已发送的命令和名义动力学模型。
它沿着历史命令的生效顺序，估计“新命令开始生效时”的 q/dq，再让 MPC 从这个估计出发。
**不会把过去目标角直接当成真实角，也不会读取被控模型的真实质量、摩擦或当前隐藏状态。**

原始观测、预测初值和预测时刻分开记录。失败时分别对观测状态、真实测试状态和实际 QP 初值做独立可行性检查。
延迟必须显式指定，不从 DDS Write 耗时猜测；真实接收时间不自动等于传感器采样时间。
首次历史命令生效前使用名义保持假设，超过原 54 ms 预测时域的末端使用明确的常量／姿态外推。
这些也是待实机辨识的假设，不能忽略。

| 组合压力条件下的候选 | 结果 | 最小外层角度余量 |
| --- | --- | ---: |
| 仅提前减速 | 0.114 s 停止 | 1.000° |
| 仅延迟补偿 | 5 s 完成，但仍几乎贴边 | 0.001513° |
| 提前减速＋延迟补偿 | **20 s 完成** | **0.264218°** |
| 实际延迟 6 ms，估计成 4 ms | 5 s 完成 | 0.250263° |
| 实际延迟 6 ms，估计成 8 ms | 5 s 完成 | 0.283728° |

4／8 ms 对照只用于检查这两个估计偏差，不证明任意抖动、丢包都能承受。
修正版 20 s 的主动命令跟踪 RMSE 为 0.92806 rad/s²；最大实际加速度约 9.05582 rad/s²，
**仍超过 QP 期望加速度的 8 rad/s² 上限**，但低于此模型 mapper 的 10 rad/s² 检查值。
这正说明模型约束不等于真实响应保证；没有把 8 放宽成 10，也不能宣称所有物理量均已严格受限。

## 4. 时间与完整流程

对姿态插值做批量计算，并减少日志 JSON 的重复标量转换，没有删检查或改变数值意义。
两种插值实现的两组 20 s 闭环，**48 个非计时数组逐元素完全一致**。
组合压力试验的控制核心 p99 从约 6.84 ms 降到 4.35 ms；这是不同批次主机测量，不是严格隔离的性能因果实验。
核心时间包含延迟估计和 MPC／mapper，**不含学习预测器、真实 DDS、包构建或任务日志全链路**，最大值仍有 6.48 ms。

另外用固定 H0、合成静止反馈、冻结 `learned_filtered` 预测器跑两次完整接管／控制／三秒退权：

| `[5,18)` 窗口 | 第一次 | 第二次 |
| --- | ---: | ---: |
| 完整离线工作 p99 | 6.035 ms | 4.862 ms |
| 完整离线工作最大值 | 9.594 ms | 5.251 ms |
| 6 ms 截止时间超限 | 26 / 2140 | 0 / 2166 |
| 最终 weight／日志丢弃 | 0 / 0 | 0 / 0 |

这两轮启用了提前减速约束，**不含尚未接入 runner 的延迟预测**。独立审计核对 3466／3501 条本地命令，
实测初值、一拍参考、只加入一次 PD、总力矩／变化率、最终零前馈均通过。
合计约 0.604% 超时，不能只挑零超时的第二轮报告，也不能把核心 4.35 ms 和本表混成“全链路通过”。
本地 packet 只做 CRC／序列化，没有 publisher。

主机已是 PREEMPT_RT 内核，但进程仍用 SCHED_OTHER，固定 CPU 2；没有改变系统实时优先级或电源设置。
固定 CPU 不等于独占核，尾部耗时仍需验证。

## 6. 09-29：完整离线任务集成

对应新增 [`hardware_mpc_delay_plan.py`](../../tools/g1_commissioning/hardware_mpc_delay_plan.py)，
以及现有 `MpcRuntime`、计时器和独立消息审计的窄范围扩展。不是新的现场控制入口。

现在同一条离线流程包含：原始反馈进入 → 冻结扰动预测器 → 命令时刻状态估计 → 实测状态 MPC →
逆动力学／候选筛选 → 完整接管／控制／退权 → SDK 消息 CRC／序列化 → 历史提交与日志。

三处关键语义已经处理：

1. 原始关节观测与扰动预测的时间起点分开记录，不把滤波网格时刻冒充原始采样时刻。
2. 学习预测器的线加速度／角加速度是 **6 ms 区间平均量**，平移时按区间重叠比例取平均；
   不再把这些平均量当成独立瞬时节点随意插值。仍不声称消除了传感器滤波相位误差。
3. 命令历史只提交最终消息序列化后再解码的 float32 值，包括 weight；候选尚未转成消息时不会提前进入历史。
   尚未提交上一条消息或最终消息与检查值不符时，会拒绝继续使用错误历史。

正常渐入／渐出的历史预测暂用 `weight × SDK总力矩 + (1−weight) × 名义重力／偏置支撑`。
**这是离线假设，不是对固件混合方式的识别结果。** 原有任务的权重斜率、力矩变化率、最终零前馈不变。
失败退出仅记录软件故障，不能由离线进程关闭推导机器人失联时会安全退权。

计时固定 CPU 2、单线程数值库、普通 SCHED_OTHER，不改系统设置；合成静止反馈、冻结 learned_filtered 模型。
输入人为延后 4 ms，命令作用时刻暂假定为“本轮开始＋6 ms”。这是用于集成的已知假设，不是测得的 DDS 时延。

| 完整 `[5,18)` 主窗口 | 第 1 轮 | 第 2 轮 |
| --- | ---: | ---: |
| 工作耗时平均 | 8.545 ms | 8.675 ms |
| 工作耗时 p99 | 9.340 ms | 9.802 ms |
| 工作耗时最大值 | 10.897 ms | 15.260 ms |
| 实际循环间隔 p50 | 12.000 ms | 12.000 ms |
| 6 ms 截止时间超限 | 1083 / 1083 | 1082 / 1082 |
| 日志丢弃／最终 weight | 0 / 0 | 0 / 0 |

**功能流程跑完，但 6 ms 时序明显未通过，不是偶发尾部超时。** 调度器跳过过期时隙，因此实际大多隔 12 ms；
没有偷偷把 MPC 配置改成 12 ms。所有主窗口消息都在假定“本轮开始＋6 ms”之后才准备好，
所以这个假定作用时刻也不能解释为真实可执行时刻。只有消息算术／记录链审计通过，不能称物理时序有效。

本轮只做了保持模型不变的优化：批量生成预测子步的身体姿态，复用首次相同状态的动力学计算，
不再计算用不到的初始保持力矩；每个后续子步仍计算自己的非线性质量矩阵／偏置，没有换成冻结动力学近似。
优化前一轮完整工作平均约 8.94 ms，优化后仍不够；不能靠删日志、减约束或忽略超时宣布通过。

113 项相关测试通过；两轮分别审计 2247／2250 条本地消息，最终退权为零、日志没有丢弃，运行期间源码哈希未变。
结果与复验命令在[完整流程证据](../../evaluation_summary/hardware_mpc_delay_lifecycle_20260929/README.md)。

**接下来不增加新的模型压力测试清单。** 离线待解决的明确问题是整链计算时间，需要针对最耗时部分优化实现，
而不是重新收集轨迹或把硬件时延假设改得更好看。必要时评估把高频状态推进／日志转换移入原生代码；本轮没有擅自扩大重构。
真实命令到电机的时延、力矩／加速度响应，以及接管／退权的物理表现，留给一次有界现场辨识；没有测力计时不声称已做绝对力矩标定。

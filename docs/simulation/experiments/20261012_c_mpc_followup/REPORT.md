# C 与 MPC：预测收益、约束、升频与计算代价

2026-10-12。纯仿真研究；未连接机器人，未修改现场配置、学习预测器或 T01～T06 启动器。
旧 C、原 MPC、原模板及既有实验记录保留。本轮产生的大体积重复输出在提取紧凑物理轨迹后清理，
保留每轮精确配置、源码哈希、失败日志、逐帧 q/qdot、瓶轴与世界系运动量，以及完整周期计时。

本轮68次启动尝试中，2次在初始化被延迟接口拒绝，66次实际物理仿真，64次完整结束、2次执行层中止。
64次完整结束中有2次发生QP回退、未通过任务检查：`mpc6_n1`（27次）和`mpc6_alpha0p01`（1次）。
其余62次通过既有任务检查，但仍需另看接触与实时性，不能将“通过任务检查”直接当作可上机。

## 如何选择

没有一个方案在六项指标、构型余量、计算耗时和延迟敏感性上全面支配其余方案。
如果按原任务优先降低三维线加速度，同时维持很小的倾角，仍优先考虑优化 MPC；
如果主要追求角运动稳定和较低计算负担，C 是有竞争力的完整方案，不应称为弱 PID 对照。
当前已有真机走停证据的仍是原 MPC；本文的优化 MPC 和升频 C 都不能冒充已上机验证。

论文建议保留 MPC 主线，同时报告位置 PID 和同执行层前馈加速度 PID 两类对照。
前者比较完整系统，后者隔离滚动优化相对“模型前馈＋单拍控制分配”的额外价值。
不能把共享的 IMU、运动学前馈、逆动力学和执行层收益全部归因于 MPC 的预测优化。

## 比较口径

统一完整 `0 <= t < 8 s`，2 ms MuJoCo 物理步，0～6.4 s 行走、随后停车。
主表使用历史 200 mm/250 g 负载；75 mm 负载另列验证。左固定 PD、腿部命令、中立位和物理执行器上限不变。
闭环全身轨迹仍会随着右臂控制变化，因此不是完全相同身体扰动的开环回放。

- 竖直倾角：每帧瓶轴与世界竖直夹角的均值。
- 平均轴摆动：相对整段归一化平均瓶轴方向的角距离 RMS。
- 线/角加速度、线/角速度：三维向量范数的 RMS。
- 线速度包含正常前进，下降不自动算改善；同时记录行走距离、速度跟踪误差和同轮左臂。
- 接触是用保存的完整物理状态重新计算碰撞几何的检查；不是估计真实机器人接触力。

完整数值见 [主要对照](SELECTED_METRICS.md)、[逐轮左右臂](ALL_METRICS.md)、
[机器可读证据](evidence_results.json)、[计时三次重复](TIMING.md) 和 [运行计数](run_counts.json)。

## 旧 C 与新 C 的构型差异

旧 C 的六项指标并非全面差于新 C。旧 C 的姿态与角速度更好，新 C 的线/角加速度只降低约 0.82%/1.04%。
新 C 的主要工程动机是较小的关节偏移和约束内控制分配，而不是宣称全面更优。

标准 6 ms 轮的最大绝对关节角：

| 关节 | 旧 C | 新 C 现场候选的仿真对应版本 |
|---|---:|---:|
| 肩 pitch | 14.59° | 5.56° |
| 肩 roll | 4.27° | 2.97° |
| 肩 yaw | 6.17° | 3.69° |
| 肘 pitch | 12.40° | 4.07° |
| 腕 roll | 6.71° | 5.61° |

肩 pitch 距 ±15°内运行边界的最小余量约 0.41° / 9.44°。
两轮都没有检测到手臂接触，故不能说“旧 C 有接触所以必须换新 C”。
更大的角度余量也不等于已证明全部姿态无碰撞；此前新 C 的 4 ms 延迟轮仍有短暂肩部接触。

## “保守范围”具体指什么

它是相对另外两组优化 MPC 的命名，不是相对最早原 MPC。
表内是扣除 margin 后的正常规划区间，顺序为肩 pitch、肩 roll、肩 yaw、肘 pitch、腕 roll。

| 配置 | 原仿真 MPC | 优化 MPC：保守范围 | 优化 MPC：加速度/姿态综合 |
|---|---|---|---|
| 肩 pitch | [-4,4]° | [-15,15]° | [-19,19]° |
| 肩 roll | [-4,2]° | [-15,15]° | [-14,11]° |
| 肩 yaw | [-20,5]° | [-20,15]° | [-24,19]° |
| 肘、腕 | ±40° | ±40° | ±44° |
| 关节速度上限 | 1 rad/s | 2 rad/s | 2 rad/s |
| 期望关节加速度上限 | 8 rad/s² | 15 rad/s² | 25 rad/s² |

“保守”不是所有五个关节区间的严格子集：例如它的 roll 区间反而比另外两组宽。
准确含义是较低加速度上限，以及 pitch/yaw/肘/腕较少的放宽。
物理力矩上限相同；执行加速度检查阈值另有不同，不能把“保守”解释成鲁棒安全证书。

## C 和 MPC 分别约束了什么

C 是任务空间姿态 PID 给出角加速度需求，随后用运动学做五变量控制分配，最后走加速度到力矩执行层。
这属于有界加权最小二乘/二次规划控制分配，PID 和优化并不矛盾。
参考 [Härkegård 的控制分配说明](https://www.research.harkegard.se/qcat/intro.html)。

| 版本 | 分配/规划约束 | 执行与局限 |
|---|---|---|
| 旧仿真 C | 无约束最小二乘后按下一拍 q、dq、ddq 逐关节裁剪；遇到不可行区间用减速回退 | 共用 MuJoCo 力矩候选检查；不是约束内最优分配 |
| 新仿真 C | 下一拍 q、dq、ddq 纳入单拍分配，可启用既有提前制动 | 力矩检查在共用执行层；仿真分配内部并未加入硬件版全部力矩约束 |
| 已准备的真机 C | 下一拍 q、dq、ddq；局部 M*a+b 总力矩及 SDK 前馈力矩约束；既有提前制动 | 带实测移动基座输入的耦合右臂模型，非全身动力学；尚未真机验证 |
| 仿真 MPC | 九步 q、dq、ddq 约束；未来状态与任务代价 | 非线性接触/候选力矩检查在执行层，非完整接触动力学嵌入 QP |
| 真机 MPC | 九步状态/加速度；冻结局部模型的总/前馈力矩约束；既有提前制动 | 只对近似模型中的规划轨迹成立，不是任意模型误差下的安全证明 |

下一拍状态约束对应 `q_next=q+dq*dt+0.5*a*dt²`、`dq_next=dq+a*dt`。
两者均没有显式整条手臂到躯干的距离约束。下一拍可行也不保证之后始终有可行解。
MPC 更早考虑未来边界是结构优势，但“有 QP”不自动推出真实安全。
名义预测与处理不确定性的鲁棒 MPC 是不同层次，见
[Rawlings、Mayne、Diehl 教材第 3 章](https://sites.engineering.ucsb.edu/~jbraw/mpc/MPC-book-2nd-edition-6th-printing.pdf)。

## 54 ms 预测为什么没有使全部指标都更低

本项目 MPC 状态为 `x=[q,dq]`（10 维），输入为五关节加速度，而非把 q、dq、ddq 都作为三个状态层级。
C 也输出五关节加速度，并共享模型与执行层。C 的单拍目标直接追踪姿态 PID 的角加速度需求、
惩罚末端线加速度和偏离回中加速度；MPC 则优化整个短窗口的姿态、角运动、线加速度、
关节偏离和输入等综合代价。两个目标不同，不能由“MPC 求最优”推出六个离线指标逐项更优。

本轮保持保守 MPC 的其他配置不变，得到以下消融：

| 预测设置 | 倾角均值 ° | 平均轴摆动 ° | 线加速度 | 角加速度 | 角速度 |
|---|---:|---:|---:|---:|---:|
| 9 步 / 54 ms | 0.09951 | 0.11506 | 2.76175 | 6.09692 | 0.04758 |
| 6 步 / 36 ms | 0.12260 | 0.13038 | 2.77005 | 6.02291 | 0.04837 |
| 3 步 / 18 ms | 0.15099 | 0.17047 | 2.78043 | 6.07309 | 0.05531 |
| 1 步 / 6 ms | 0.47758 | 0.68062 | 2.65771 | 6.82633 | 0.11179 |
| 9 步，未来扰动全部保持当前测量 | 0.60827 | 0.71996 | 3.15040 | 10.33567 | 0.16447 |

一拍 MPC 的线加速度虽小，但有肩部接触、姿态/角速度恶化，行走距离也变少，不能按这一列判优。
它还发生27次QP失败/回退，因此是缩短窗口后的整体闭环后果，不是无回退理想优化器的纯数学比较。
三步到九步的额外线加速度收益只有约 0.7%，主要收益是姿态/摆动和角速度。
当前模板的步态周期为 800 ms，54 ms 只占 6.75%，不是提前看到整个落脚周期。

C 若仍用当前 IMU 做前馈、但不使用模板首段预测（`old6_current_hold`），线/角加速度为 3.38459/8.27339；
使用模板后为 2.98836/5.76726。它的近期预测前馈本来就在发挥很大作用。
`old6_noff` 进一步去掉分配目标中的已知加速度补偿项，不能当成只关闭预测器的消融。
逆动力学执行层仍保留；没有把整个系统所有模型项关掉。

代价取舍也有直接证据：保守 MPC 只把角加速度权重从 0.005 提到 0.02，
角加速度从 6.09692 降到 5.65753，低于旧 C 的 5.76726；线加速度从 2.76175 升到 2.82518。
这说明此前角加速度劣势不全是 MPC 架构能力不足，也包含所选取舍。
姿态综合 MPC 将同一权重从 0.003 改到 0.02，得到 0.07438°/0.08604°、
2.71785、5.66371、0.45705、0.04576。只作取舍证据，未升级为现场配置。

运动学输入只有五个自由度，无法任意独立设定三个线加速度和三个角加速度。
此外，局部线性化、预测误差、执行层映射和接触都影响最终物理指标。
本轮未精确分离每一种误差的占比，不能将所有差距归咎于某一条公式错误或单一物理极限。

## 升频 C 的实现与边界

仿真旧 C 每拍计算十个节点的运动学，但实际仅用当前节点和首区间。
研究分支改成只计算实际用到的节点；单步动作测试与完整任务指标核对通过。
因单点/批处理浮点运算顺序不同，整段轨迹不是逐位相同，但六项指标差异极小，见 efficiency_parity.json。
**真机 C 原来已经只计算一个节点**，不能将本次仿真提速当成额外的真机提速成果。

原仿真模板为 6 ms 网格，原始训练记录目前不在本机。这里使用原有校验通过的模板派生研究预览：
每个新查询点选择最近的已过去旧锚点，在该行的同一坐标系内插值姿态/节点量，
用时间重叠比例平均区间加速度。当前测量节点保持原样，不读取未来仿真状态。
例如 4～8 ms 加速度用旧 0～6 和 6～12 ms 区间均值各一半。
它不能重建原模板中没有的高频冲击，不是重新训练出的 4 ms/2 ms 预测器。
派生预览分别提供 9×4 ms、9×2 ms；C 仍仅使用首段。既有3 ms区间前视保留。
现场 learned_filtered 是另一套 H0 预测链，本轮未修改，也未解除其6 ms接口检查。

最终保留的 4 ms研究候选 `field4_post36` 相对原新 C 的实际变化为：

| 配置 | 原新 C（6 ms） | 4 ms研究候选 |
|---|---:|---:|
| 控制周期 | 6 ms | 4 ms |
| 姿态 PID Kp / Ki / Kd | 400 / 50 / 40 | 600 / 50 / 49 |
| 回中 kp / kd | 24 / 8 | 36 / 10 |
| 线加速度权重 | 0.4 | 0.4 |
| 分配正则 | 0.012 | 0.012 |
| 约束分配、提前制动 | 启用 | 保持 |
| 物理力矩、q/dq/ddq 限制 | 既有值 | 保持 |
| 模板 | 原6 ms | 派生4 ms |

另跑同样增益的6 ms版本 `field6_post36`，用于区分升频与调参。
4 ms 的执行映射从每6 ms区间内0、4 ms更新，变为每4 ms区间内0、2 ms更新；
所以这个升频实验也改变执行重算时序，不能全部归因于 PID 求解次数。

旧 C 只改周期并不会全面改善。早期4 ms新 C 原参数触发 NO_SAFE_TORQUE；
Kp=600、回中24/8 的好看数据伴随肩部接触，回中36/10之后才通过标准轮接触检查。
2 ms虽然可以推进仿真，但完整计算周期超期，且有关节接触，不作为实机候选。

延迟工具只允许请求0、2、4 ms并要求小于控制周期。两次尝试4 ms周期、4 ms有效延迟的请求
在初始化校验处被拒绝；保留记录但不计为物理仿真控制失败，也没有绕过检查。
有效延迟对照使用2 ms，结果另见机器可读记录和最终结论。

|---|---:|---:|---:|---:|---:|---:|
| 旧 C，6 ms | 0.05814 | 0.07332 | 2.98836 | 5.76726 | 0.45913 | 0.03963 |
| 原新 C，6 ms | 0.10297 | 0.12453 | 2.96401 | 5.70744 | 0.46341 | 0.04434 |
| 本轮 C，4 ms、回中36/10 | 0.03583 | 0.05717 | 2.94302 | 4.86421 | 0.46380 | 0.03734 |
| 同增益 C，6 ms、回中36/10 | 0.07812 | 0.09631 | 3.01772 | 5.83844 | 0.46497 | 0.04241 |

本轮4 ms C相对旧 C：两种角度降低38.4%/22.0%，线加速度降低1.52%，角加速度降低15.66%，
角速度降低5.79%；线速度增加1.02%，未解释为改善或恶化。相对同增益6 ms版本，
线/角加速度降低2.48%/16.69%。同时改变了控制周期和执行重算时序，模板也做了派生转换。

这些是仿真测量，不代表硬件转矩跟踪或延迟鲁棒性已证明。

| 同为2 ms指令延迟 | 倾角均值 ° | 平均轴摆动 ° | 线加速度 | 角加速度 | 角速度 |
|---|---:|---:|---:|---:|---:|
| 保守 MPC，6 ms | 0.10140 | 0.11168 | 2.81937 | 6.38353 | 0.04870 |
| 旧 C，6 ms | 0.05462 | 0.07583 | 3.08139 | 6.59462 | 0.05176 |

4 ms C在零额外延迟下的角运动优势没有保持到这个延迟场景；保守MPC对其两种倾角和三项动态量均更好。

## 完整计算耗时

CPU7串行三次、单线程BLAS、SCHED_OTHER的完整周期结果如下，单位ms：

| 方案 | 周期 | 均值范围 | P99范围 | 三次最大 | 超期/区间数 |
|---|---:|---:|---:|---:|---:|
| 旧C原计算 | 6 | 2.832～2.847 | 3.063～3.198 | 3.975 | 0/3987 |
| 旧C只算所需节点 | 6 | 2.726～2.771 | 2.938～3.334 | 3.904 | 0/3987 |
| 原新C只算所需节点 | 6 | 2.871～2.879 | 3.200～3.459 | 3.999 | 0/3987 |
| 本轮4 ms C | 4 | 2.502～2.530 | 2.782～3.163 | 3.866 | 0/5982 |
| 保守MPC | 6 | 3.879～3.893 | 4.175～4.275 | 5.055 | 0/3987 |
| 2 ms C探索 | 2 | 1.871～1.894 | 2.109～2.272 | 2.689 | 794/11964 |

优化十节点到单节点主要改善平均耗时，P99并非每次都降低；未宣称已完成全部性能优化。
4 ms全周期有计算可行性，但最坏样本3.866 ms已接近预算；2 ms约6.64%区间超期，明确不采用。
仿真按固定物理步推进，不会自动把wall-clock超期反馈成丢帧或延迟，故必须独立检查计时。

之前已准备真机C的两条无网络日志回放（本轮核对记录）平均完整计算为2.308/2.202 ms、
P99为2.786/2.511 ms、最大3.149/2.898 ms，均无6 ms超期。
均值分解：预测器0.907/0.826 ms，控制核心1.002/0.985 ms，命令包阶段0.347/0.340 ms。
来源：[保留的回放记录](../../../g1_field_validation/evidence/20261012_c_preparation/replay_summary.json)。
它不包含真实DDS发送、执行器响应和新闭环反馈，不能据此直接解除真机6 ms接口限制。

因此保留4 ms分支用于后续迁移研究，当前T系列上机入口仍使用原新C的6 ms配置。

## 复现

使用既有 g1_mpc 环境和四个 C++ 仿真库；启动器会在缺库时整体报错，不将缺库误算控制失败。

```bash
cd /home/fjk/g1_ws/hold-my-beer-mpc
taskset -c 0-17 /home/fjk/miniforge3/envs/g1_mpc/bin/python \
  tools/experiments/c_mpc_followup/run_study.py \
  tools/experiments/c_mpc_followup/initial.json --cpus 0,2,4
```

其余清单为 `ablation.json`、`tradeoffs.json`、`contact_followup.json`、`final_checks.json`、`matched_delay.json`。
`final_checks.json` 须使用 `--cpus 7`，不并行跑其他仿真，才与表中串行计时条件相符。
启动器按名称保留结果并跳过已完成项；如需新复测，应复制清单并改成新的唯一 name，勿覆盖旧数据。
使用 `audit_results.py` 检查接触/真实关节余量，使用 `report.py` 导出表格；现场默认入口完全不调用本目录。

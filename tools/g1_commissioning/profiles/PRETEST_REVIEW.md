# A2 首次悬挂试验：准入审核不等于试验结果

2026-09-15 修订，仅适用于独立的 A2 小幅、短时、有人看护的悬挂静态试验。
不扩展为落地行走、整机底层控制、无人值守或故障注入许可。

## 审查结论

旧的 `normal_release_confirmed` 混淆了“交还方案已审核”和“真机交还已成功”；
把后者要求为首次 A2 的前提会形成循环门槛。删除这种前置结果要求，改为
`normal_release_plan_reviewed`：审核代码／离线轨迹的 weight 退零过程，明确交还
不符合预期时的人工中止方法。**实际交还是否平顺，是 A2 的验收结果。**

旧的 `loss_recovery_confirmed` 被解释为必须先确认目标固件全部断线／崩溃行为，
对这个首次受保护的小幅试验过于笼统。改为 `loss_response_plan_reviewed`：
**不依赖未验证的自动停止假设，而是审核失联时的人工处置和禁止自动恢复的流程。**
这不是删除异常处置要求，也不是把“未知 watchdog”改成“已验证安全”。

两项为 v2 新字段，默认仍为 false。v1 配置及旧字段拒绝加载，不自动把旧 true
转换成新含义；历史日志、历史未运行结论不改写。审核人应把依据写入本次记录，
而不是因为程序报错就勾选。profile 摘要明确记录“方案审核不等于硬件验证”。

## 首次试验前怎样审核

| 项目 | 需要的依据 | 不要求事先完成的实验 |
| --- | --- | --- |
| 正常交还方案 | 官方 Arm SDK weight 接口、当前退零实现及离线预览；确认正常停止依赖有效通信，异常不等待回位 | 不要求这台机器已跑过同一次 A2 并成功交还 |
| 失联处置方案 | 按“旧目标／weight 可能继续有效”处理；独立于开发电脑／网线的停止方法；禁止自动恢复；故障后停止用户进程，先建立可控状态，再只读检查，重新审核才能重启 | 不要求首次控臂前故意拔网线、kill -9 或诱发失控 |
| 现场停止准备 | 官方说明与本机实测退阻尼相符；遥控器由现场人员掌握；悬挂承重、人员避开活动范围；若停止无效，明确能否安全使用官方关机流程，不能冒险伸手抓关节 | 不把无用户输出时的按键测试冒充持续 Arm SDK 输出中的抢占试验 |
| 执行条件 | 新鲜 FSM=4、CRC／tick／速度等状态检查通过，映射和本次数字参数审核，无竞争用户 publisher，精确 EXECUTE 确认 | 不要求重新做已完成的 A0 问卷或把 getter 失败值伪装为有效 |

如果本机已有证据表明遥控器保护被禁用、失效或存在控制权冲突，不能仅凭“有方案”
开始输出；必须先解决该问题。手册方法与本机现象一致，是首次试验的停止准备依据，
不是保证所有故障都可处置的认证。小角度是命令范围，不是任意故障的运动范围上限。

## 本次已有证据和待记录结果

- 已有：L2+B 后读回 FSM=1、用户观察到下垂；L2+↑ 后 FSM=4、用户观察到站姿。
  用户确认无其他程序控臂；悬挂脚离地由用户报告。
- 已有：停止联锁离线测试，以及三秒真机只读监测通过。它不是独立急停；没有实测
  在真实控臂期间的按键抢占，也没有做断网故障注入。
- 开始前由电脑完成：按实际证据整理单独的 v2 profile，审核既定 0.02 rad、weight 0.1、
  6.2 秒方案，重新读模式／姿态。不是直接运行默认 DRAFT 模板，也不扩大幅度。
- A2 中／结束后记录：实际是否响应、另一只手／腰／腿是否异常、是否回到初始目标、
  weight 是否退零、机器人接回是否平顺。不能只凭进程 exit=0 宣布这些结果通过。
- 尚未知：固件失联超时和最后目标／权重的处理、各类故障下的停止时延。
  不因此要求先做有风险的断线测试，也不把它们用于后续自动运行的安全论证。

## 依据与判断边界

- 官方 [Arm5 示例](https://github.com/unitreerobotics/unitree_sdk2/blob/main/example/g1/high_level/g1_arm5_sdk_dds_example.cpp)
  展示了逐渐降低 weight 并最后发送零权重。**不是照搬该示例的初始化幅度／权重。**
- 官方 [XR Motion 说明](https://github.com/unitreerobotics/xr_teleoperate/wiki/Motion)
  描述内置运控与上肢控制的接入／退出；不证明本机所有故障行为。
- 本地《操作指南》遥控章节与《使用手册》异常／关机章节提供停止处置方法；
  本机按键实际效果见 `docs/g1_field_validation/sessions/20260915_A2_STOP_INTERLOCK.md`。
- 把前置条件改为“有依据的方案审核”，而把实际成功留作实验结果，是本项目对
  首次受保护试验的工程判断，不宣称为 Unitree 认证或对所有运行阶段通用的豁免。
